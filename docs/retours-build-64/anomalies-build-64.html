Causes des anomalies

Les tickets du backlog ne sont pas autant de problèmes indépendants. Trois causes en expliquent la majorité, et chacune forme un Epic. Le reste (textes, design, comportement de l'assistant) est regroupé dans un quatrième Epic.

EPIC C1

L'app appelle dans la base des objets qui n'existent pas

Avant chaque enregistrement d'un devis, l'app appelle la fonction check_quote_creation_limit ou check_and_record_trial_edit dans Supabase. Aucune des deux n'existait. L'appel échouait, donc aucun devis ne s'enregistrait.

En découlent l'envoi impossible, les brouillons absents de la liste, le numéro 2026-0001 réutilisé, les lignes ajoutées en double et le PDF de secours (points à la place des virgules, pied de page en anglais). Interventions échoue de la même façon, sur une table absente.

EPIC C2

Deux générations d'écrans cohabitent

Les anciens écrans lisent la base directement. Les nouveaux passent par l'API du site. Ils ne voient pas les mêmes données, ce qui explique les écrans qui se contredisent.

Sont concernés : Nouveau chantier, « Mon Chantier », Infos Chantier, Planning, Plus → Tâche, Profil Entreprise. C'est aussi là que se trouvent l'ancienne direction artistique et la plupart des fautes de texte.

EPIC C3

Des règles métier fausses

Un chantier passe « Clôturé » dès que son avancement atteint 100 %, sans regarder si un procès-verbal de réception est signé. Sans devis, l'avancement se calcule sur les tâches : une seule tâche cochée suffit.

Le procès-verbal se signait sans aucun contrôle, y compris sur un chantier vide, et rapportait des jetons du premier mois.

EPIC C4

Finitions : assistant, textes et design

Des anomalies sans cause commune : l'assistant devis qui montre ses coulisses, les noms d'offre différents selon l'écran, les fautes, le bouton ✦ qui recouvre d'autres boutons, la barre d'état illisible, les onglets coupés.

D-1 · bloque KPRO-10, KPRO-20

Quand un chantier est-il clôturé ?

Le testeur demande un devis signé avant la clôture. Cela empêcherait pour toujours de clôturer un chantier ajouté à la main, « trouvé ailleurs », que le même testeur propose de garder.

Recommandation : exiger le procès-verbal signé, pas le devis.

État : la recommandation est appliquée au sprint 1 (KPRO-10), pour ne pas laisser l'anomalie en place. Elle reste à confirmer. Deux choix provisoires vont avec : un procès-verbal se signe dès qu'il y a un devis signé ou une tâche faite, et les jetons ne sont attribués que si le devis est signé.

KPRO-1

Le devis guidé ne s'enregistre pas et ne part pas

BugTrès hauteComposant : DevisEpic C1Terminé
Constat
À l'envoi, l'écran affiche « PostgrestException… Could not find the function public.check_quote_creation_limit ». Le devis ne part pas et n'est jamais enregistré.
Cause
L'app appelle deux fonctions de la base avant chaque enregistrement. Elles n'existaient pas.
Résolution
Migration 0019_limites_devis_app.sql : crée les deux fonctions. Elles répondent toujours « autorisé » et ne touchent à aucune donnée.
Vérification
Exécutée en production le 24 novembre. La requête de contrôle renvoie allowed = true.
Reste
Le plafond de l'offre gratuite (D-6). Le message technique montré à l'artisan en cas d'échec (KPRO-9).

Migration exécutée en production

Fichier supabase/migrations/0019_limites_devis_app.sql. Peut être relancée sans risque.

create or replace function public.check_quote_creation_limit(p_user_id text)
returns table (allowed boolean, reason text)
language sql
stable
as $$
  select true, null::text;
$$;

create or replace function public.check_and_record_trial_edit(p_user_id text, p_quote_id text)
returns table (allowed boolean, reason text)
language sql
stable
as $$
  select true, null::text;
$$;

-- Appelables par un utilisateur connecté seulement (comme l'app le fait).
revoke execute on function public.check_quote_creation_limit(text) from public, anon;
revoke execute on function public.check_and_record_trial_edit(text, text) from public, anon;
grant execute on function public.check_quote_creation_limit(text) to authenticated, service_role;
grant execute on function public.check_and_record_trial_edit(text, text) to authenticated, service_role;

-- L'API de Supabase relit la liste des fonctions tout de suite.
notify pgrst, 'reload schema';

Rapport du sprint 3

Corrigé le 25 novembre 2026. Les cinq tickets sont « Prêt à livrer » : l'analyse ne signale aucune erreur, 361 tests passent côté app et 557 côté site. Commit 48c0a76 poussé le 25 novembre : la partie site est en ligne, la partie app attend un nouveau build.

Ce que l'analyse a montré

  • L'app ajoute par défaut trois frais à chaque devis : coordination 10 %, aléas 5 %, décennale 8 %, soit 23 % de plus. Le devis guidé ne les montrait pas.
  • Le site ne lisait pas ces frais dans un devis fait par l'app. Son PDF partait donc des lignes seules, alors que le total enregistré les comprend.
  • La bibliothèque affichait le taux de référence de la famille (50 € de l'heure), le devis celui du profil (75 €). Le site avait le même écart.

Ce qui n'est pas encore prouvé ni fait

  • Aucun ticket n'a été rejoué sur un téléphone. Le PDF du site pour un devis de l'app est à relire à la recette.
  • Le bloc des signatures qui part seul sur une deuxième page n'a pas été traité.
  • L'adresse du chantier et le nom du client ne sont repris sur le PDF que s'ils ont été saisis dans le devis.

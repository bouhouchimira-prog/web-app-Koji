Causes des anomalies

Les 46 tickets ne sont pas 46 problèmes indépendants. Trois causes en expliquent la majorité, et chacune forme un Epic. Le reste (textes, design, comportement de l'assistant) est regroupé dans un quatrième Epic.

EPIC C1

L'app appelle dans la base des objets qui n'existent pas

Avant chaque enregistrement d'un devis, l'app appelle la fonction check_quote_creation_limit ou check_and_record_trial_edit dans Supabase. Aucune des deux n'existait. L'appel échouait, donc aucun devis ne s'enregistrait.

En découlent l'envoi impossible, les brouillons absents de la liste, le numéro 2026-0001 réutilisé, les lignes ajoutées en double et le PDF de secours (points à la place des virgules, pied de page en anglais). Interventions échoue de la même façon, sur une table absente.

EPIC C2

Deux générations d'écrans cohabitent

Les anciens écrans lisent la base directement. Les nouveaux passent par l'API du site. Ils ne voient pas les mêmes données, ce qui explique les écrans qui se contredisent.

Sont concernés : Nouveau chantier, « Mon Chantier », Infos Chantier, Planning, Plus → Tâche, Profil Entreprise. C'est aussi là que se trouvent l'ancienne direction artistique et la plupart des fautes de texte.

EPIC C3

Des règles métier fausses

Un chantier passe « Clôturé » dès que son avancement atteint 100 %, sans regarder si un procès-verbal de réception est signé. Sans devis, l'avancement se calcule sur les tâches : une seule tâche cochée suffit.

Le procès-verbal se signait sans aucun contrôle, y compris sur un chantier vide, et rapportait des jetons du premier mois.

EPIC C4

Finitions : assistant, textes et design

Des anomalies sans cause commune : l'assistant devis qui montre ses coulisses, les noms d'offre différents selon l'écran, les fautes, le bouton ✦ qui recouvre d'autres boutons, la barre d'état illisible, les onglets coupés.

L'ordre va de ce qui débloque le plus de monde, le plus vite, à ce qui se voit le moins. Le sprint 0 ne demandait aucun nouveau build : il agit sur le build 64 déjà installé.

Décisions à prendre

Six questions restent ouvertes. Aucune ne bloquait le sprint 0. Chacune bloque les tickets indiqués.

D-1 · bloque KPRO-10, KPRO-20

Quand un chantier est-il clôturé ?

Le testeur demande un devis signé avant la clôture. Cela empêcherait pour toujours de clôturer un chantier ajouté à la main, « trouvé ailleurs », que le même testeur propose de garder.

Recommandation : exiger le procès-verbal signé, pas le devis.

État : la recommandation est appliquée au sprint 1 (KPRO-10), pour ne pas laisser l'anomalie en place. Elle reste à confirmer.

Responsable : Direction

D-2 · bloque KPRO-36

Quel message sur l'écran Urgences ?

Le testeur croit la fonction pas encore prête. Dans le code elle est active et réservée aux offres payantes.

À décider : « Bientôt disponible » ou « Réservé aux offres Pro et Business ».

Responsable : Direction

D-3 · bloque KPRO-35

Un seul nom pour l'offre gratuite

Elle s'appelle « Essai gratuit », « Koji Essai » ou « Offre Start » selon l'écran.

Recommandation : « Start », comme sur le site.

Responsable : Direction

D-4 · bloque KPRO-37

Les renvois « sur le site » passent-ils chez Apple ?

Neuf écrans de l'app invitent à changer d'offre sur le site. Apple encadre les renvois vers un paiement hors de l'app.

À décider : garder, reformuler ou retirer ces textes.

Responsable : Direction

D-5 · bloque KPRO-30

Quel calcul pour les frais du devis ?

Le site et l'app ne calculent pas l'assurance décennale sur la même base, donc pas le même total.

À décider : le calcul de référence, puis les deux s'alignent.

Responsable : Direction et Responsable technique

D-6 · suite de KPRO-1

Plafond de devis de l'offre gratuite dans l'app

Les fonctions créées au sprint 0 répondent toujours « autorisé ». L'app ne limite donc pas le nombre de devis enregistrés.

À confirmer : pas de plafond dans l'app pour l'instant, ou un plafond à définir.

Responsable : Direction

KPRO-1

Le devis guidé ne s'enregistre pas et ne part pas

BugTrès hauteComposant : DevisEpic C1Terminé
Constat
À l'envoi, l'écran affiche « PostgrestException… Could not find the function public.check_quote_creation_limit ». Le devis ne part pas et n'est jamais enregistré.
Cause
L'app appelle deux fonctions de la base avant chaque enregistrement. Elles n'existaient pas.
Résolution
Migration 0019_limites_devis_app.sql : crée les deux fonctions. Elles répondent toujours « autorisé » et ne touchent à aucune donnée.
Vérification
Exécutée en production le 24 novembre. La requête de contrôle renvoie allowed = true.
Reste
Le plafond de l'offre gratuite (D-6). Le message technique montré à l'artisan en cas d'échec (KPRO-9).

Migration exécutée en production

Fichier supabase/migrations/0019_limites_devis_app.sql. Peut être relancée sans risque.

create or replace function public.check_quote_creation_limit(p_user_id text)
returns table (allowed boolean, reason text)
language sql
stable
as $$
  select true, null::text;
$$;

create or replace function public.check_and_record_trial_edit(p_user_id text, p_quote_id text)
returns table (allowed boolean, reason text)
language sql
stable
as $$
  select true, null::text;
$$;

-- Appelables par un utilisateur connecté seulement (comme l'app le fait).
revoke execute on function public.check_quote_creation_limit(text) from public, anon;
revoke execute on function public.check_and_record_trial_edit(text, text) from public, anon;
grant execute on function public.check_quote_creation_limit(text) to authenticated, service_role;
grant execute on function public.check_and_record_trial_edit(text, text) to authenticated, service_role;

-- L'API de Supabase relit la liste des fonctions tout de suite.
notify pgrst, 'reload schema';

KPRO-2

L'invitation d'un compagnon est vide

BugHauteComposant : ÉquipeEpic C4Terminé
Constat
L'écran « Invitation prête » montre un cadre vide, et le SMS s'ouvre sans texte.
Cause
Côté serveur. L'invitation est créée avec un code, mais le contrôle de validité cherchait un autre champ, jamais écrit. Toute invitation était donc jugée invalide et renvoyée vide.
Résolution
Le contrôle lit le code (lib/equipe-pro.js). Cela répare aussi les invitations créées depuis moins de 7 jours et la connexion du compagnon par code, qui échouait pour la même raison.
Vérification
Test unitaire mis à jour sur la forme réelle de l'invitation.
KPRO-3

L'assistant affiche une balise technique et des astérisques

BugHauteComposant : Assistant devisEpic C4Terminé
Constat
« [RESULTAT_ECRITURE] bien reçu » et « **Plafond** » apparaissent dans la conversation.
Cause
Le modèle recopiait la balise d'un message interne, et l'écran affiche le texte tel quel, sans mise en gras.
Résolution
Le serveur retire la balise et les astérisques avant l'affichage, pendant l'arrivée du texte et sur la réponse finale (lib/devis-chat-texte.js). Les consignes interdisent aussi de les écrire. Vaut pour le site et pour l'app.
Vérification
Quatre tests unitaires, dont un qui coupe le texte à n'importe quel endroit.
KPRO-4

L'assistant se répète et montre ses coulisses

BugMoyenneComposant : Assistant devisEpic C4Terminé
Constat
Il redemande une confirmation après « ajoute sans me demander », raconte ses recherches, cite une erreur technique et demande à l'artisan de vérifier lui-même les doublons.
Résolution
Nouvelles consignes (lib/devis-chat-prompt.js) : un accord donné d'avance vaut confirmation, aucun récit des recherches, aucun détail technique, et l'assistant lit lui-même l'état du devis avant de proposer de réessayer.
Limite
Le respect des consignes dépend du modèle. À juger à la recette.
KPRO-5

Le Calendrier n'affiche pas le nom de la tâche

BugMoyenneComposant : CalendrierEpic C4Terminé
Constat
La tâche « Peindre les murs » apparaît sous « Démarrage · TEST 2 », avec pour seul détail « lot Autres tâches ».
Résolution
Le détail de la ligne donne le nom des tâches du jour, trois au plus puis le compte. Le faux lot « Autres tâches » n'est plus affiché (lib/calendrier-pro.js). Le titre « Démarrage · chantier » reste, comme sur la maquette.

KPRO-6

Un procès-verbal se signe sur un chantier vide

BugHauteComposant : ClôtureEpic C3Terminé
Constat
Sur un chantier à 0 %, sans devis signé, le procès-verbal se signe et indique « Travaux réceptionnés : devis ».
Résolution
Le serveur refuse le procès-verbal quand le chantier n'a ni devis signé ni tâche faite, avec un message clair. Le procès-verbal n'écrit plus « devis » sans numéro (app/api/cloture, lib/cloture-chantier.js).
Choix fait
« Devis signé ou au moins une tâche faite », pour ne pas bloquer un chantier ajouté à la main. La règle définitive dépend de D-1.
Reste
L'écran de l'app avant signature : KPRO-20.

Critères d'acceptation de la recette, sur le build 64

  1. Devis guidé (KPRO-1, KPRO-21). Demander une ligne à l'assistant : elle apparaît une seule fois et la mention « Devis enregistré » s'affiche. Envoyer le devis : aucune erreur. Le devis est visible dans l'onglet Devis.
  2. Assistant (KPRO-3, KPRO-4). Aucune balise, aucun astérisque. Après « ajoute sans me demander », la ligne est ajoutée sans question de confirmation.
  3. Compagnon (KPRO-2). Le cadre affiche le lien et le code. Le SMS est prérempli.
  4. Calendrier (KPRO-5). « Peindre les murs » apparaît sous « Démarrage · TEST 2 ».
  5. Procès-verbal (KPRO-6). Sur un chantier sans devis signé ni tâche faite, la signature est refusée avec le message « Rien à réceptionner pour l'instant ».
  6. Parcours (KPRO-8). « Faire un devis » ouvre le devis guidé.

The mobile recap page lib/features/quote/quote_detail_screen.dart is now the central edit surface (client wanted everything editable there, "comme Odoo", phone-only). The intermediate "Créer vos ouvrages" screen (room_task_screen.dart) is now BYPASSED from every entry point: room_selection_screen pushes `/quote/detail` directly (new devis), and home_screen "Devis en cours → edit" pushes `/quote/detail` with the saved `q` (recap rehydrates via `_loadExistingQuote` since `q` has an id). The `/quote/room-details` route still exists in router.dart but is no longer navigated to. Added 2026-06-14:

**Flow (2026-06-16):** the "Créer vos ouvrages" screen (room_task_screen.dart) is bypassed. room_selection_screen.dart now pushes `/quote/detail` (recap) directly with `QuoteDetailArgs(data: quoteCreationProvider.toMap())`; chantier_devis_screen edit-mode also goes straight to the recap. quote_detail_screen `initState` calls `_seedEmptyLotsFromSelectedRooms()` which turns `widget.data['roomIds']` into empty lots (`_roomOrder`+`_lotMeta`, title via `_getRoomLabel`) so the chosen pièces show as fillable lots. room_task_screen.dart + the `/quote/room-details` route still exist but are no longer in the create/edit path.

- "Ajouter un lot" button (full-width, below lots) → `_addLot` inserts a new room/lot at the TOP of `_roomOrder` (roomId = `lot_<ts>`), so it's immediately visible — fixing the client bug "new ouvrage gets hidden in the middle".
- Per-lot toolbar `_buildLotActions`: Ouvrage / Fourniture / Note. All inserts go to index 0 of the lot via `_insertLineAtTop`.
- Ouvrage picker = `_OuvrageHistorySheet` (DraggableScrollableSheet, searchable) reading `ouvrageLibraryProvider`. It now offers all 3 sources of the old "Créer vos ouvrages" screen, via `_pickOuvrage()`: **Historique** (search list), **Créer** (onCreateBlank → `_blankOuvrage`, editable inline), **Bibliothèque d'ouvrages** (onOpenLibrary → `OuvrageLibraryScreen(pickMode:true)` then `_askCoefficientReduction` coeff/réduction prompt). Selecting gives the line a fresh `ouvrage_<ts>` id (NOT linked to the library row). Both `_addOuvrageToLot` and `_addSousOuvrage` use `_pickOuvrage()`.
- Fourniture picker = `_FourniturePickerSheet` reading `allFournituresProvider` (Fournisseurs module); line id `fourniture_<ts>`, stores `fournisseurId/Name`, `fournituresUnitPrice = prixVenteHT`.
- Line `more_vert` menu adds: Commentaire…, Ajouter un sous-ouvrage (`_addSousOuvrage`, inserts right after parent with parentTaskId), Ajouter une fourniture, Supprimer.
- Comment lines (`comment_` prefix, `isComment`) carry text only (0 €), shown as italic note rows IN THE RECAP only. They are an internal annotation and are NOT rendered on any devis PDF (client request 2026-06-16): `devis_pdf_service._pieceRows` skips `isComment` items, and returns no widgets (no empty lot title) when a lot has only notes. The `isComment`/`commentaire` flags still flow from signature_screen / chantier_client_screen / recap _generateQuote but are now ignored by the PDF.
- Unit picker: the Qté field's unit pill is tappable (`onSublabelTap` on `_inputField` → `_editUnite`), opening a chip sheet from `_uniteOptions` (m², ml, forfait, h, kg, %…) + custom unit — matches the Odoo unit dropdown the client sent.
- Fourniture creation (2026-06-17): the picker's "Nouvelle" button now opens the FULL `AddFournitureScreen` (Navigator.push) instead of a minimal dialog, and that screen `Navigator.pop`s the created `Fourniture` so the devis inserts it. AddFournitureScreen's "URL de l'image" field was replaced by a gallery picker (`_pickImageFromGallery` → `FournitureRepository.uploadFournitureImage` to the `fourniture-images` Supabase bucket). Categories in its dropdown still come from its own list; consider switching to `productCategoriesProvider` later.
- (Older) Inline supplier/fourniture creation: `_FourniturePickerSheet` had a "Nouvelle" button (`_createFournitureInline`) that creates a fourniture (and optionally a new fournisseur via `addFournisseur`) through `fournitureRepositoryProvider`, invalidates `allFournituresProvider`, and returns it — so "ajoute un fournisseur / tout d'ici" works without leaving the recap.

**Odoo-style product picker (2026-06-16):** `_FourniturePickerSheet` redesigned with a left **CATÉGORIE DE PRODUITS** sidebar (`_categorySidebar`, "Tous" + per-category counts) + right product list (`_productList`/`_productCard` with thumbnail, price, supplier, "Ajouter" button), matching the client's Odoo screenshot. Categories come from Supabase table `product_categories` via `productCategoriesProvider` / `FournitureRepository.getProductCategories()`, falling back to `kFournitureCategories` (fourniture_model.dart) when empty/offline. SQL: supabase/create_product_categories.sql (global rows user_id=NULL + per-user RLS; seeded with the 29-category list). The inline-create dialog now has a Catégorie dropdown sourced the same way (saves `category: selectedCategory`, no longer hardcoded 'Autre'). NOTE: supabase/ is git-ignored now — run the SQL manually in the Supabase SQL editor.

**Side effect to guard:** recap comment lines (`comment_…`) and standalone fournitures (`fourniture_…`) are saved as `quote_tasks` rows. They are NOT executable work. Places that filter them out via an `_isNonTaskLine` guard (task_id prefix `comment_`/`fourniture_`, or isComment/isFourniture flags):
- `QuoteTaskRepository.getDevisTasksForChantier` — À faire list + planning/scheduling.
- `QuoteRepository.saveQuote` auto-create of **project_tasks** (Strategy 1 tasksMap + Strategy 2 expenses) — previously a note became a project task ("note shows up as task"). Fixed 2026-06-16.
- `chantier_client_screen` — comment excluded from `_suivi` titles + lot HT (still passed to PDF with isComment/commentaire).

Workers get tasks from RPC `get_worker_tasks` (assigned/scheduled only), so filtering the planning source covers them too. PDF paths (signature_screen, recap _generateQuote, chantier_client_screen) DO pass comment/fourniture lines through with `isComment`/`commentaire`/`isFourniture` flags so devis_pdf_service renders the note (italic) and splits fournitures. `getQuoteTasks` (recap reload) must still return ALL lines — never filter there.

**Separate bug fixed 2026-06-16:** `QuoteRepository.saveQuote` inserted into `projects` without `title` (NOT NULL) → `23502 null value in column "title"`, silently skipping all project/task auto-creation. Now sets `title: 'Chantier <client|reference>'`.

**Orphan devis → chantier shows 0 devis (fixed 2026-06-16):** a devis with `chantier_id = null` never appears in the chantier dashboard (`chantierQuotesProvider`/`streamChantierQuotes` strict-match `chantier_id`) nor À faire. Added `ChantierRepository.linkOrphanQuotesToChantier(chantierId)` (matches orphan quotes by client name == chantier reference, or siteAddress == chantier address — same hard signals as `getDevisTasksForChantier`) and call it from `chantier_dashboard_screen` initState, then invalidate `chantierQuotesProvider` + `chantierAFaireTasksProvider`.

**RPC json cast crash (fixed 2026-06-16):** RPCs that `RETURNS json` (e.g. `get_chantier_worker_activity`, `get_company_worker_reports`) could return a JSON String or `Map<dynamic,dynamic>` elements; `result.cast<Map<String,dynamic>>()` threw "type 'String' is not a subtype of type 'Map<String, dynamic>'" on the Suivi ouvriers screen. Added `ChantierRepository._asMapList()` (jsonDecode if String, deep-convert each Map) and made the screen's `_list()` use `whereType<Map>().map(Map.from)` instead of `.cast`.

**Header fully editable + Aperçu + Créer ouvrage (2026-06-17):**
- Tapping the header card (`_buildHeaderCard`, now wrapped in InkWell with an edit pencil hint) opens `_editHeader` — a bottom sheet editing company (name/address/phone/email/SIRET/RCS/TVA + logo via `_pickAndUploadLogo` → `userRepositoryProvider.uploadBusinessLogo`), client (name/address/email), lieu d'exécution and validité.
- Aperçu: AppBar eye icon → `_previewPdf` builds the devis via `_buildQuoteData()` (extracted from `_generateQuote`, shared by save + preview) and opens it with `DevisPdfService().generate` + `Printing.layoutPdf` — no save.
- Line card mode fields (client request 2026-06-17): in Forfait mode the line shows ONLY the Prix HT field (Qté + Temps hidden); in Calculé mode it shows ONLY Qté + Temps (Prix HT hidden). Fournitures always show Qté + Prix u. HT (no Temps). `_promptNewOuvrage` form: when unité = 'forfait' it hides Taux horaire and the middle field becomes "Prix forfait (€)", returned as tempsHU=1 × tauxHoraire=price.
- "+ Créer" in the ouvrage sheet now calls `_promptNewOuvrage` (form: désignation/unité/temps/taux) instead of dumping a generic "Nouvel ouvrage" blank line. `_blankOuvrage` removed.

Calc unchanged and verified per [[quote-coefficient-pitfall]]: MO = qty × tempsHU × tauxHoraire × conditionCoeff; fourniture line total = qty × fournituresUnitPrice; ouvrage mère total = own line + sum of sous-ouvrages (children summed once in lot total, not double-counted).

Round-trip: new fields persisted in tasksMap inputs AND top-level (parentTaskId, lineType, commentaire, fournisseurId/Name) so re-entry edit and `_fetchDetails` DB reload both rehydrate. quote_repository.saveQuote does delete-then-insert of rooms/tasks, so new lots/lines are created automatically.
